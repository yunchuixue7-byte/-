## 9. 已知的坑与验证技巧（避免重蹈覆辙）

- **文件编辑权限（迁移后已变化）**：项目现在在 D 盘，Edit/Write 可直接读写，不再需要绕道 computer_use。旧机器 E 盘"not read yet / 无权限"的坑不再适用。
- **System.Text.Json 与 NaN**：`double.NaN` 会被序列化成字符串 `"NaN"`，反序列化不认（报 `Cannot get the value of a token type 'String' as a number`），导致整个设置文件加载失败、静默回退默认值。**窗口位置字段必须用可空 `double?`（null 哨兵），不要用 NaN。** 这是已修复的根因（2026-10-13）。
- **XAML 默认选中陷阱**：下拉框在 XAML 里写 `SelectedIndex="4"` 会在控件初始化时触发 SelectionChanged，把刚加载的设置覆盖成默认值。正确做法：XAML 不写默认 SelectedIndex，恢复设置时用 `_isRestoring` 标志屏蔽保存逻辑（已修复）。
- **GUI 模拟点击不稳定**：豆包/WPS 窗口会反复抢焦点，用模拟点击操作游戏窗口不可靠。验证设置记忆的正确姿势：**直接改 settings.json + 重启游戏 + 截屏确认**。
- **全屏截图**：cu.screenshot() 对超大屏幕会报 "Base64 超 5MiB"。改用 PowerShell 的 CopyFromScreen 存 jpg（Add-Type 顺序必须 System.Windows.Forms 在前、System.Drawing 在后）。
- **临时诊断手法**（用完必须清理）：把值拼进窗口标题用 `Get-Process Gomoku.App | Select MainWindowTitle` 读；或写 `%TEMP%\gomoku-diag.txt`。改代码加日志前先确认能还原。
- **棋盘扩展相关约定**：方向枚举 0=上 1=下 2=左 3=右；`ExtendStep=9`（半块）；世界数组 5×Size、`ViewRow/ViewCol` 初始 0,0；`MoveResult.BoardFull=5`。占满后落子、超时自动落子、AI 落子三条路径都会触发 `ShowBoardFullPanel()`；扩展失败（每方向最多 4 次）会提示"已达棋盘扩展极限"并重新弹面板。动画期间 `_shifting=true`，鼠标/悔棋/重开被屏蔽，返回主菜单会停掉动画计时器。改动评估/胜负相关代码时注意：连子扫描用世界坐标 `GetCell(row,col)`（越界返回 Empty 自动停止），**不要用 `Position.IsValid(Board.Size)` 这种 0-18 边界判断**。
- **沙盒里启动游戏窗口要审批，别反复试**（2026-10-14）：`Start-Process ...Gomoku.App.exe` 属于"启动外部程序"，在 DSH 沙盒里会弹审批；没人点确认时命令会一直挂在后台（表现为 `[still running after 60000ms]`，进程实际没起来）。结论：**GUI 冒烟测试交给用户手动做**（跑 exe / 双击 bat），命令行只做 `dotnet build` + `dotnet test` 两步验证。

- **AI 思考必须放后台线程**（2026-10-19 修复）：`AlphaBetaEngine.SelectMove` 是深度 2-4 的 Negamax，每节点对候选点做全盘 `PatternEvaluator.Evaluate`（O(361×4)），中后期一步可达千万级操作。若在 UI 线程同步调用，点击落子后整窗冻结、动画不播。正确模式：`Task.Run` 后台搜索 + `Dispatcher.BeginInvoke` 回主线程落子，思考期间用 `_aiBusy` 屏蔽悔棋/重开。
- **AI 慢的真正 bug：candidateLimit 未生效**（2026-10-20 修复）：`AlphaBetaEngine` 构造参数 `candidateLimit` 一直没被使用，`SelectMove` 与 `Negamax` 每层遍历 `GetCandidateMoves` 返回的全部候选（2 格邻域去重后可达几十个），深度 4 档搜索树按几十^4 膨胀，大师/巅峰档一步可算十几秒。修复：`OrderCandidates` 排序后 `.Take(_candidateLimit)`（10-16 个），速度提升约一个数量级、棋力不变。
- **AI 取消必须保证棋盘回滚**（2026-10-20）：给 `IPlayerEngine.SelectMove` / `GameController.TryPerformAiMove` 增加 `CancellationToken` 参数后，`PlaceStone` → 递归 → `UndoLast` 必须包 try/finally，否则搜索中途被取消（认输）时棋盘残留未撤销的模拟落子，导致后续悔棋/落子错乱。取消在循环入口 `ThrowIfCancellationRequested` 检查即可。
- **AI 思考时认输**（2026-10-20）：原来 `_aiBusy` 一刀切屏蔽了认输按钮。现在认输流程先 `_aiCts.Cancel()` 中止后台搜索，再 `Resign()` 结算；`ContinueWith` 回主线程时若 token 已取消则直接复位 `_aiBusy` 并跳过落子后处理。悔棋/重开仍屏蔽（破坏对局状态风险高）。
